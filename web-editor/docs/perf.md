# 미리보기 성능 측정 (태스크 5 시점)

테스트: `tests/e2e/perf.spec.ts`. 큰 파일은 커밋하지 않으므로 `PERF_DIR`을 줄 때만 실행한다.
```
PERF_DIR=<clip1~5.mp4 폴더> npx playwright test perf
```
- 자료: 1080×1920 30fps H.264 8Mbps, 12초 클립 5개를 메인 트랙에 이어 붙인 60초 프로젝트
- 환경: 샌드박스 Linux, Chrome 154 헤드리스, **GPU 없음**(소프트웨어 디코딩/그리기), 자동 재생 허용 플래그 없음(기본 정책)
- 두 번 측정(1차: 자동 재생 허용 플래그 사용, 2차: 기본 정책 + 영상 클립 파형 추가 후)

| 항목 | 1차 | 2차 | 기준 |
|------|-----|-----|------|
| 재생 10초 동안 초당 그리기 횟수 | 58~61 | 56~61 (클립 경계에서 56 한 번) | 목표 60fps, 57 미만인 초 1번 이하 |
| 그리기 사이 최대 간격 | 23~55ms | 23~71ms (클립 경계에서 71ms 한 번) | — |
| 영상·소리 차이 | 3~4ms | 4~16ms | 2프레임(67ms) 이내 |
| 재생 중 긴 작업(50ms 초과) | 0건 | 0건 | 0건 |
| 드래그·트림 중 긴 작업(50ms 초과) | 0건 | 0건 | 0건 |

- 클립이 바뀌는 순간(다음 클립 요소가 재생을 시작할 때) 한 번 짧게 느려진다(최대 71ms, 약 2프레임). 이 경계 처리는 태스크 13 성능 기준을 만들 때 다시 본다.
- GPU가 없는 환경에서 측정한 값이다. Windows 노트북 Chrome은 하드웨어 디코딩을 쓰므로 이보다 나쁘지 않을 것으로 예상하지만, 확인은 사용자 확인 1(실제 촬영본)에서 한다. 수용 기준 A1 테스트는 태스크 13에서 CI용으로 만든다.
