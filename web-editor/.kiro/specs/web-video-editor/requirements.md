# 요구사항 — 웹 영상 편집기 (1단계 MVP)

## 개요
캡컷 데스크톱처럼 타임라인을 보면서 직접 편집하는 **순수 정적 웹앱**. Windows 11 + Chrome에서 주소만 열면 설치 없이 동작한다.
미리보기는 렌더링 대기 없이 실시간이며, 최종 결과만 MP4로 내보낸다.

## 범위
- 포함: 1단계 MVP (아래 R1~R12)
- 제외: 2단계(트랜지션, 필터, 속도 조절 UI, 키프레임, SRT, 템플릿), 3단계(Whisper 자막)
- 산출물에 포함하지 않음: .exe, .bat, PowerShell, Electron, Windows 경로, 백엔드 서버, Python, 설치형 ffmpeg

## 용어
- **프로젝트**: 캔버스 설정, 트랙, 클립, 미디어 목록을 담은 편집 상태
- **클립**: 타임라인 위 한 구간. 종류는 영상, 이미지, 오디오, 텍스트
- **프레임**: 시간의 기본 단위. 프로젝트 fps는 30이다

## R1. 실행 환경
- R1.1 앱은 `vite build`로 만든 정적 파일(`dist/`)만으로 동작해야 한다. 런타임에 서버 API를 호출하지 않는다.
- R1.2 앱은 Windows 11의 최신 Chrome(데스크톱)에서 https 또는 localhost로 열었을 때 동작해야 한다.
- R1.3 WebCodecs를 쓸 수 없는 환경(예: file://, 미지원 브라우저)이면 앱이 한국어로 원인과 해결 방법을 안내해야 한다.
- R1.4 코드와 문서에 OS 파일 경로를 하드코딩하지 않는다.
- R1.5 `web-editor/dist`는 GitHub Actions로 GitHub Pages에 자동 배포되어야 하고, 사용자는 그 주소로 접속한다.
- R1.6 모든 코드는 `web-editor/` 안에 둔다. 저장소의 기존 Python/Electron 앱은 수정하지 않는다.

## R2. 한국어 UI
- R2.1 사용자에게 보이는 모든 문자열(버튼, 메뉴, 툴팁, 오류, 진행 메시지)은 한국어여야 한다.
- R2.2 UI 문자열은 `src/i18n/ko.ts` 한 파일에 모은다. 수용 기준: 컴포넌트 JSX에 하드코딩된 영어 UI 문자열 grep 결과가 0건이어야 한다.

## R3. 화면 구성
- R3.1 좌측 패널에는 [미디어 | 텍스트 | 오디오 | 효과] 탭이 있어야 한다. 효과 탭에는 "2단계에서 제공 예정"이라는 안내만 표시한다.
- R3.2 중앙 미리보기의 기본 비율은 9:16(1080×1920)이고, 16:9(1920×1080)와 1:1(1080×1080)로 바꿀 수 있어야 한다.
- R3.3 미리보기 아래에는 재생/정지 버튼과 `현재 시간 / 전체 시간`(mm:ss.ff 형식)을 표시한다.
- R3.4 우측 패널에는 선택한 클립의 속성을 표시한다. 영상/이미지 클립은 위치, 크기, 회전, 투명도, 볼륨을 보여 준다. 텍스트 클립은 텍스트 서식, 오디오 클립은 볼륨과 페이드를 보여 준다. 속도는 1단계에서 1배로 고정된 읽기 전용 값으로 표시한다.
- R3.5 하단은 멀티트랙 타임라인이다. 영상 트랙 2개 이상, 텍스트 트랙 1개, 오디오(BGM) 트랙 1개 이상이 있어야 하고, 플레이헤드, 줌 슬라이더, 스냅(자석) 토글을 둔다.

## R4. 미디어 가져오기
- R4.1 드래그앤드롭과 파일 선택 대화상자로 mp4, mov, jpg, png, mp3, wav를 가져올 수 있어야 한다.
- R4.2 가져온 영상은 미디어 패널에 썸네일로 표시한다. 영상 클립은 타임라인에 필름스트립(연속 썸네일)으로 표시한다.
- R4.3 오디오 파일과 오디오가 있는 영상은 타임라인에 파형을 표시한다.
- R4.4 브라우저가 디코딩할 수 없는 파일은 파일 이름과 이유를 한국어로 알려 주고 거부한다(예: 이 브라우저에서 재생할 수 없는 코덱).
- R4.5 미디어 패널의 썸네일을 타임라인 트랙으로 끌어다 놓으면 해당 위치에 클립이 생겨야 한다. 트랙 종류가 맞지 않으면 놓을 수 없다(예: 오디오 파일을 텍스트 트랙에 놓기).

## R5. 타임라인 편집
- R5.1 클립을 드래그해 같은 트랙이나 같은 종류의 다른 트랙으로 옮길 수 있어야 한다.
- R5.2 클립의 양 끝을 드래그해 트림할 수 있어야 한다. 영상/오디오 클립은 원본 길이를 넘어 늘어나지 않는다. 이미지/텍스트 클립은 길이 제한이 없다.
- R5.3 플레이헤드 위치에서 선택한 클립을 분할하면 두 개의 클립이 되어야 하고, 각 클립은 원본의 해당 구간을 정확히 재생해야 한다(프레임 단위).
- R5.4 선택한 클립을 삭제할 수 있어야 한다.
- R5.5 스냅이 켜져 있으면 드래그/트림 중인 클립의 가장자리가 8px 이내에 있는 다른 클립 가장자리, 플레이헤드, 0초 지점에 달라붙어야 한다.
- R5.6 같은 트랙의 클립은 겹치지 않아야 한다. 겹치는 위치에 놓으면 가장 가까운 빈 구간으로 보정하고, 들어갈 자리가 없으면 원래 위치로 되돌린다.
- R5.7 줌 슬라이더와 Ctrl+휠로 타임라인을 확대/축소할 수 있어야 한다.
- R5.8 트랙 순서가 화면 합성 순서가 된다. 위쪽 영상 트랙이 아래쪽 영상 트랙보다 앞에 보인다. 텍스트 트랙은 항상 가장 앞에 보인다.

## R6. 실시간 미리보기
- R6.1 미리보기는 Canvas와 `<video>`로 실시간 합성해야 하며, 편집하면 사전 렌더링 없이 다음 프레임에 반영해야 한다.
- R6.2 목표 재생 프레임 레이트는 60fps(화면 갱신 기준)이다. 영상 콘텐츠는 30fps 타임라인 기준으로 보여 준다.
- R6.3 정지 상태에서 플레이헤드를 옮기면(스크럽) 해당 프레임을 보여 줘야 한다.
- R6.4 미리보기 위에서 선택한 클립을 드래그해 옮기고, 모서리 핸들로 크기를, 회전 핸들로 회전을 조절할 수 있어야 한다. 변경 내용은 우측 속성 패널에도 즉시 반영된다.
- R6.5 영상과 오디오 재생은 동기화되어야 한다. 기준: 재생 중 영상과 오디오의 차이가 2프레임(약 67ms) 이내.

## R7. 텍스트
- R7.1 텍스트 탭에서 텍스트 클립을 추가할 수 있어야 한다.
- R7.2 글꼴은 Pretendard와 Noto Sans KR 중에서 고를 수 있어야 한다. 두 글꼴은 앱에 포함해 배포하며 외부 CDN에 의존하지 않는다. 한글이 □로 깨지면 안 된다(미리보기와 내보낸 MP4 모두).
- R7.3 글자 크기, 굵기, 색상, 외곽선(색상/두께), 배경 박스(켜기/끄기, 색상, 투명도, 여백), 정렬을 설정할 수 있어야 한다.
- R7.4 등장/퇴장 시간은 텍스트 클립의 시작/끝으로 정하며, 타임라인 트림이나 속성 패널의 숫자 입력으로 바꿀 수 있어야 한다.
- R7.5 미리보기에서 텍스트 클립을 더블클릭하면 내용을 바로 수정할 수 있어야 한다.

## R8. 오디오
- R8.1 영상/오디오 클립마다 볼륨을 설정할 수 있어야 한다(0~200%).
- R8.2 클립마다 페이드 인/아웃 길이를 설정할 수 있어야 한다(0~5초). 타임라인 클립에 페이드 구간을 표시한다.
- R8.3 오디오 트랙(BGM)에 mp3/wav를 올릴 수 있어야 하고, 트랙 음소거를 할 수 있어야 한다.
- R8.4 미리보기와 내보내기의 볼륨/페이드 결과가 같아야 한다.

## R9. 단축키
- R9.1 Space 재생/정지, S 분할, Delete(및 Backspace) 삭제, Ctrl+Z 실행 취소, Ctrl+Y 및 Ctrl+Shift+Z 다시 실행, ←/→ 1프레임 이동.
- R9.2 텍스트 입력 칸에 포커스가 있으면 단축키가 동작하지 않아야 한다.
- R9.3 드래그 한 번(이동, 트림, 크기, 회전)은 실행 취소 기록 1개로 남아야 한다.

## R10. 저장/불러오기
- R10.1 편집 상태를 IndexedDB에 자동 저장해야 한다(변경 후 1초 이내).
- R10.2 가져온 미디어 원본은 IndexedDB에 저장해 새로고침 후에도 다시 가져올 필요가 없어야 한다.
- R10.3 새로고침하면 마지막 프로젝트의 트랙, 클립, 속성, 캔버스 비율, 플레이헤드 위치가 그대로 복원되어야 한다.
- R10.4 프로젝트를 JSON 파일로 내보내고 가져올 수 있어야 한다. JSON에는 편집 상태와 미디어 목록(이름, 크기, 길이)만 포함하고 미디어 원본은 포함하지 않는다. 가져올 때 IndexedDB에 없는 미디어는 "미디어 다시 연결" 목록으로 보여 주고, 사용자가 파일을 선택해 다시 연결할 수 있어야 한다.
- R10.5 저장 공간이 부족하면 한국어로 알려야 한다.

## R11. MP4 내보내기
- R11.1 MP4(H.264 영상 + AAC 오디오), 30fps로 내보내야 한다. 해상도는 프로젝트 비율에 맞춘다(9:16이면 1080×1920).
- R11.2 브라우저가 WebCodecs H.264 인코딩을 지원하면 WebCodecs(하드웨어 가속 우선) + Mediabunny로 인코딩한다.
- R11.3 브라우저 WebCodecs에 AAC 인코더가 없으면 Mediabunny 공식 AAC 인코더 확장(`@mediabunny/aac-encoder`, WASM)을 쓴다.
- R11.4 *(2단계로 이동)* WebCodecs VideoEncoder를 쓸 수 없는 브라우저에서만 ffmpeg.wasm으로 인코딩하고, 느리다는 안내를 표시한다. 1단계에서는 R1.3 안내 화면만 보여 준다.
- R11.5 내보내는 동안 진행률(%), 경과 시간, 남은 예상 시간을 표시해야 한다.
- R11.6 취소 버튼으로 언제든 멈출 수 있어야 하고, 취소하면 자원을 해제하고 편집 화면으로 돌아와야 한다.
- R11.7 File System Access API를 쓸 수 있으면 저장 위치를 고르게 하고 파일에 바로 스트리밍한다. 쓸 수 없으면 다운로드로 저장한다.
- R11.8 내보낸 영상은 미리보기와 같은 결과여야 한다(같은 합성 코드 사용).

## R12. 프록시 *(보류: 사용자 확인 1에서 실제 촬영본의 미리보기가 끊길 때만 진행)*
- R12.1 미디어별로 "미리보기용 저해상도 프록시 만들기" 옵션을 제공한다. 긴 변이 1080px을 넘는 영상을 가져오면 이 옵션을 제안한다.
- R12.2 프록시가 있으면 미리보기에는 프록시를 쓰고, 내보내기에는 항상 원본을 쓴다.
- R12.3 프록시 생성 진행률을 표시하고, 생성 중에도 편집할 수 있어야 한다.

# 2단계·3단계 추가 요구사항 (확인 1 뒤 합의)

## 공통 규칙 추가
- R0.1 모든 AI 기능은 브라우저 안에서 로컬로 실행한다. 유료 API, Google API를 쓰지 않고 외부 API 키를 요구하지 않는다.
- R0.2 AI 모델은 처음 한 번만 내려받아 브라우저에 캐시한다. 내려받는 동안 진행률을 보여 준다.
- R0.3 이펙트·필터·트랜지션은 WebGL 셰이더로 구현하고, 미리보기와 내보내기는 같은 코드를 쓴다(R11.8 유지).
- R0.4 캡컷의 이름, 로고, 에셋을 복제하지 않는다. 기능과 사용 흐름만 참고한다.

## R7 확장 (텍스트 강화, 1단계)
- R7.6 스타일 프리셋 20종(외곽선형, 박스형, 그림자형, 네온형, 쇼츠 자막형 등). 클릭하면 적용되고, 적용 뒤에도 개별 값을 고칠 수 있다.
- R7.7 등장/퇴장 애니메이션 8종: 페이드, 팝, 타자기, 슬라이드 4방향, 바운스, 줌. 길이를 조절할 수 있다.
- R7.8 긴 문장은 안전 영역 너비에 맞춰 자동으로 줄바꿈한다(한글은 띄어쓰기 단위).
- R7.9 안전 영역 가이드선(쇼츠 UI에 가려지는 상·하단)을 켜고 끌 수 있다. 가이드선은 내보낸 영상에 포함되지 않는다.

## 2단계
- R13 필터·배경 흐림·트랜지션·효과는 WebGL2 셰이더로 처리한다(배치·텍스트는 Canvas 2D 유지, 설계 §13). WebGL을 쓸 수 없으면 효과만 끄고 한국어로 알린다.
- R14 트랜지션 10종(디졸브, 슬라이드 4방향, 줌 인/아웃, 와이프, 블러, 흔들림, 글리치). 클립 경계에 끌어다 놓고 길이를 조절할 수 있다.
- R15 필터 프리셋 12종 + 조정 슬라이더 6종(밝기, 대비, 채도, 색온도, 선명도, 비네트), 영상 효과 6종(흔들림, 번쩍임, 줌 펄스, 흑백, 레트로, 블러).
- R16 키프레임: 위치, 크기, 회전, 투명도, 볼륨. 이징은 선형과 부드럽게.
- R17 속도 0.25~4배, 음 높이 유지 옵션.
- R18 캔버스 배경(단색, 블러 채우기)과 오버레이(이미지/PNG 로고, 도형, 화면 속 화면).
- R19 나레이션이 나올 때 BGM을 자동으로 줄인다(덕킹). 영상에서 소리만 떼어 오디오 트랙으로 분리할 수 있다.

## 3단계
- R20 자동 자막: 브라우저에서 Whisper를 돌려 한국어 음성을 단어별 타이밍으로 인식하고, 카라오케/단어 강조 자막을 텍스트 클립으로 만들어 바로 수정할 수 있게 한다.
- R21 무음 자동 컷: 음량을 분석해 말이 없는 구간을 찾아 미리 보여 주고 한 번에 잘라낸다.
- R22 인물 배경 제거: 배경을 지우거나 흐리게 하거나 이미지로 바꾼다.
- R23 자동 리프레임: 16:9 → 9:16 전환 때 얼굴을 따라가는 키프레임을 자동으로 만든다.
- R24 브랜드 키트: 로고, 브랜드 색상 3개, 기본 글꼴, 자막 스타일, 인트로/아웃트로를 저장하고 한 번에 적용한다. 프로젝트를 템플릿으로 저장하고 새 영상을 템플릿으로 시작할 수 있다.
- R25 워터마크가 없고, 잠긴 기능이 없다.

# 완료 기준 5가지 (G1~G5) — 하나라도 NO면 완료가 아님

사용자가 정한 최종 판단 기준이다. "된다"고 말하려면 **측정 방법**까지 통과해야 한다.

| ID | 기준 | 측정 방법 (이 조건을 만족해야 YES) | 검증 위치 |
|----|------|------------------------------------|-----------|
| **G1** | 버튼을 누르면 설명 없이도 바로 결과가 보인다 | ① 주요 버튼(가져오기, 텍스트 추가, 프리셋, 분할, 삭제, 내보내기, 효과)은 누른 뒤 **1초 안에 화면에 눈에 보이는 변화**가 생긴다. ② 누르면 아무 일도 없는 버튼(막다른 길)이 **0개**. ③ 빈 화면에는 다음에 할 일이 한국어로 적혀 있다. ④ 아직 없는 기능은 회색으로 두고 "2단계 제공 예정"처럼 이유를 적는다 | 태스크 10.6 자동 테스트 + 확인 2 |
| **G2** | 실제 촬영본으로 재생할 때 끊기지 않는다 | 사용자의 실제 스마트폰 촬영본(1080p 이상)으로 만든 60초 프로젝트에서 ① 재생 중 프레임 드롭 **5% 미만**, ② 플레이헤드를 옮긴 뒤 화면이 바뀌기까지 **200ms 이내**. 무거운 원본은 자동으로 저해상도 미리보기(프록시)를 쓴다 | 태스크 10.6(자동 프록시) + 확인 2(실파일) |
| **G3** | 내보낸 MP4가 미리보기와 똑같다 | 같은 프로젝트에서 서로 다른 **3개 이상의 프레임**을 골라, 미리보기 픽셀과 내보낸 MP4를 다시 디코딩한 픽셀의 차이가 **채널당 평균 3 이하**. 해상도·프레임 수·길이도 일치 | 태스크 10 자동 테스트 (CI) |
| **G4** | 새로고침해도 작업이 남아 있다 | 편집 → 새로고침 → **트랙·클립·속성·미디어·플레이헤드가 모두 같다**. 탭을 강제로 닫은 뒤 다시 열어도 마지막 편집이 남아 있다(저장 주기 1초 이내) | 태스크 9 자동 테스트 (CI) |
| **G5** | 한 편 만드는 시간이 캡컷보다 짧거나 같다 | 정해진 시나리오(1080p 클립 5개 가져오기 → 3번 분할 → 자막 3개 → BGM 1개 → 30초 영상 내보내기)를 처음부터 끝까지 수행한 시간을 잰다. 사용자가 **같은 시나리오를 캡컷으로 했을 때보다 짧거나 같아야** 한다 | 태스크 10.6(작업 시간 표시) + 확인 2(사용자 측정) |
